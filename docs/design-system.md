# 设计系统 · Material 3 Expressive × Apple HIG

我自己的设计系统，用于统一我开发的所有项目。本文是入口层，管四份文档共用的那一层：主张、分工、原则、决策顺序，以及视觉与体验这两层语言怎么取。

取值在[视觉系统](visual-system.md)，行为在[交互系统](interaction.md)，文字在[内容系统](content.md)。

本文的引号约定：「」引代码里真实出现的标识符与取值；“”提及行文中的某个说法或概念。

## 主张

> M3E for expression. HIG for experience. Design Tokens for consistency. Platform conventions for adaptation.

四句有先后。

Material 3 Expressive 给表现力与系统化的视觉取值。Apple Human Interface Guidelines 给清晰、克制、层级与自然交互。Design Tokens 把两者收成同一份数字。平台惯例决定落地形态。

这不是把两套风格混在一起，也不是模仿某个平台的外观。前三句合起来是一套设计语言，第四句说明这套语言不要求所有媒介长得一样：一张图、一个网页、一段纯文本可以是同一套语言的三种形态。

## 核心分工

| 层 | 来源 | 负责 |
| --- | --- | --- |
| Visual Expression | M3E | 色彩、字体、形状、层级、组件与动态表现力 |
| UX Principles | Apple HIG | 清晰、克制、直觉、层级、反馈、连续性与可访问性 |
| Consistency | Design Tokens | 统一 Color、Typography、Shape、Spacing、Size、Elevation、Motion 与 State |
| Adaptation | Platform Conventions | 尊重 Web / 手机 / 桌面及不同输入方式的原生习惯，不机械复制 Android 或 iOS 外观 |

M3 与 HIG 管的不是同一件事。M3 给的是可以直接实现的取值，HIG 不规定长相，规定的是质量与偏向。冲突时按[决策优先级](#决策优先级)排。

## 设计原则

追求：

- Expressive but not noisy.
- Minimal but not empty.
- Playful but not childish.
- Premium but not ornamental.
- Fluid but not distracting.
- Consistent but not monotonous.

优先通过 Typography、Spacing、Color、Shape、Hierarchy、Motion 建立信息关系，而不是滥用 Card、Border、Divider、渐变和装饰。

颜色表达语义与层级；Shape 应有层次；Motion 应解释状态变化与空间关系，而不是单纯炫技。

优先复用已有 Tokens 与 Components，避免硬编码和局部创造新的视觉规则。相同语义、状态和操作必须保持一致。

## 决策优先级

发生设计冲突时：

```text
Usability               可用性
→ Accessibility         可达性
→ Clarity               清晰
→ Consistency           一致
→ Platform conventions  平台惯例
→ Expressiveness        表现力
→ Decoration            装饰
```

视觉表现力不能以牺牲可用性为代价。

规范里声明的几处「让位」就是这张表在起作用：与内容冲突时让位给内容，与外部实现并排时让位给同源，与平台惯例冲突时让位给惯例。**让位不等于放宽**——可机械验证的条目（术语、符号、标点、命名、开关）没有让位余地，让位的理由写在代码注释里。

不要机械复制 Material，也不要模仿 Apple 外观。

## 哲学

五组边界。每一组左边是要达到的，右边是不许越过的。

| 要 | 不要 |
| --- | --- |
| 有表现力 | 制造视觉噪声 |
| 简洁 | 因为追求极简而丢信息 |
| 有活力 | 过度娱乐化 |
| 精致 | 依赖无意义的装饰 |
| 流畅 | 动画干扰正在做的事 |

另有一条：统一，但不要求所有元素完全相同。相同语义、相同状态、相同操作保持一致；重要程度不同、功能不同、交互性质不同的元素可以有不同表现。

## 视觉语言 · M3 Expressive

视觉这一层借鉴 Material 3 Expressive，取九样：

- 有表现力的色彩
- 语义化的色彩角色
- 清晰的字体层级
- 有表现力的形状
- 有意义的容器
- 明确的视觉重心与层级
- 有意图的对比
- 可随内容调整的构图
- 有表现力的运动

把它简化成「大圆角 + 卡片 + 鲜艳颜色 + 动画」是误读。表现力来自颜色、形状、字体、空间、层级与运动之间有目的的组合，不是任何单独一项拉满。

## 体验原则 · Apple HIG

这套系统从 Apple HIG 取两层。两层不冲突：九条管做出来的东西达到什么质量，八条管拿不准时偏向谁。

### 九条：体验要达到的质量

| 原则 | 意味着 |
| --- | --- |
| Clarity 清晰 | 一处只放一类信息；短反馈不铺陈；一条消息至多三句 |
| Deference 尊重内容 | 装饰不压内容；一个画面只有一个视觉重心 |
| Hierarchy 层级 | 字号、空间、字重、颜色一起定层级；不靠颜色单独区分等级 |
| Depth 深度 | 分层用容器色与圆角差；高度克制，不叠容器，不用阴影堆层次 |
| Directness 直接 | 名称与动作同名；能做一步就不做两步 |
| Feedback 反馈 | 长任务先给中间反馈；拿不到资源要说一声，不静默丢弃；降级安静，日志留痕 |
| Consistency 一致 | 一个数据源、一个入口、一条写入路径；同一状态在所有产物里是同一种表现 |
| Progressive Disclosure 渐进呈现 | 概览到明细逐层展开；正文只留下一步 |
| Accessibility 可达 | 文字回退信息等价、触控区达标、焦点可见、颜色不作唯一通道 |

### 八条：拿不准时偏向谁

Apple 在 2026 年 6 月重新引入的八条设计原则（Purpose 到 Delight），是整份 HIG 的基础。逐条译法在[交互系统](interaction.md#八条原则的译法)。

## 令牌

所有视觉实现来自令牌，不在版式里另定数值。现有令牌能表达设计意图就复用。同一种数值在两处出现就是缺陷。只有现有系统表达不了、且具有普遍意义的新需求，才加令牌。

十类令牌：

| 类别 | 管什么 |
| --- | --- |
| Color | 语义角色色，取值见[视觉系统](visual-system.md#色彩) |
| Typography | 字阶与字重，见[视觉系统](visual-system.md#形状--字阶--高度) |
| Shape | 圆角档位，同上 |
| Spacing | 间距阶梯 |
| Size | 结构尺寸（版心、视口、容器宽高） |
| Elevation | 高度档位，同上 |
| Border | 描边色一档；能用容器色差分层就不用描边 |
| Opacity | 状态层与遮罩 |
| Motion | 时长与曲线 |
| State | 交互状态层 |

分工不能混。**系统层说「是什么」，版式层只说「摆在哪儿」**：色值、字号、圆角、阴影的字面量一个都不许出现在版式层，一律取令牌。

## 颜色

颜色先表达语义与层级，其次才是装饰。角色色有 Primary、Secondary、Tertiary、Surface、Container、Error、Outline 等。业务代码不直接依赖具体色值。

| 不做 | 理由 |
| --- | --- |
| 大量硬编码颜色 | 换主题时改不干净 |
| 无意义的渐变 | 不表达层级 |
| 每个模块一套主题色 | 并排出现就是两套设计 |
| 只靠颜色表达状态 | 色觉障碍与灰度转发下信息丢失 |
| 为了“高级感”滥用低对比度 | 对比度是可达性，不是审美 |

颜色要能回答四件事：什么最重要、什么可以操作、什么属于同一层级、此刻是什么状态。系统外的颜色（头像主色、用户自选色）只保留色相，明度与彩度换成系统取值。取值与推导见[视觉系统](visual-system.md#色彩)。

## 字体

Typography 是建立层级的主要工具。size、weight、line-height、tracking、contrast 五样一起用，区分眉标、标题、副标题、小节、条目、页脚六层。

不要只靠颜色区分信息等级。不要出现大量意义接近、参数只差一点的文字样式——那通常是没查字阶就新写了一个。

## 形状

Shape 有层级与语义。重要程度不同、功能不同、交互性质不同的元素可以有不同的圆角。允许 rounded、pill / capsule、有表现力的几何、非对称构图，但每一处都要有目的。

容器之间用圆角差分层。不要让所有东西都是同一个圆角矩形。

## 间距与构图

优先用空间建立关系，不用边框与分割线。

```text
靠得近  →  分到一组
留白   →  层级
大小   →  重要程度
对齐   →  顺序
```

不做 Card 套 Card，不做到处都在的分隔线，不给每个元素套独立容器。判据只有一条：删掉这个容器之后信息关系还清楚，就删掉它。

## 组件

组件属于同一套系统，继承同一份 Color、Typography、Shape、Spacing、Motion 与 State。优先复用已有组件，不为某一个页面临时造一个视觉相似、实现独立的组件。

组件之间可以有不同表现，但共用同一套语法。清单见[视觉系统](visual-system.md#组件)。

## 状态

任何交互元素都要考虑完整状态，不只是默认状态。

| 状态 | 怎么表达 |
| --- | --- |
| default | 默认容器色 |
| hover / pressed | 状态层：悬停一档、按下一档，用当前文字色叠在元素自己的层上 |
| focused | 可见的焦点环 |
| selected | 容器色加一档，或用圆角差；导航用指示条 |
| disabled | 弱化文字色，不用描边色写字 |
| loading | 说清在等什么 |
| success / warning / error | 状态符号，见[内容系统](content.md#状态符号) |
| empty | 空不是故障，与失败分开 |

位图类产物没有悬停与按压，这几个状态没有对应物。状态之间的变化要清晰、一致、可预期：同一个状态在所有产物里是同一种表现。

## 动效

动效只碰 `transform` 与 `opacity`——这两样不触发布局，移动端才不抖。时长与曲线收在令牌里。外壳不设 `transform` / `filter` / `backdrop-filter`。

动效要帮助用户理解发生了什么、来自哪里、影响了什么。不做无意义淡入，不为炫技延长操作时间，不做阻碍连续操作的动画。节奏要能关。

没有补间动画的媒介里，动效落在消息的时序上：下一条什么时候出现，一件事拆成几条说。见[交互系统](interaction.md#节奏)。

## 平台适配

设计语言统一，实现尊重媒介与输入方式。同一种语言按 Web、手机、桌面、触摸、鼠标、键盘、大屏、小屏调整具体交互与布局。

适配的对象是媒介与容器，不是把界面做成同一个。同一套原则落在图片、富文本、纯文本上，越往下越朴素，信息不减少。

**Consistency ≠ identical implementation**：保持的是设计语言，不是把不同项目做成同一个。项目之间的差异按这一条归档。

## 设计之前

动手做任何页面、组件或视觉元素之前，先回答十问：

1. 它解决什么问题？
2. 最重要的信息是什么？
3. 用户首先应该注意到什么？
4. 哪些元素属于同一层级？
5. 哪些信息可以弱化或延后？
6. 有没有现成能复用的令牌或组件？
7. M3E 的表现力体现在哪里？
8. HIG 的清晰、层级、尊重内容与流畅能改善哪一处体验？
9. 符合这个平台与输入方式的习惯吗？
10. 把装饰全部删掉之后，信息结构还成立吗？

先定信息结构，再做视觉。

## 检查清单

- [ ] 取值来自令牌，版式层没有新写一个相似的数
- [ ] 容器删掉之后信息关系还清楚吗
- [ ] 状态齐了吗：默认、选中、禁用、加载、成功、失败、空
- [ ] 颜色不作唯一通道，第二个通道补了吗
- [ ] 动效只碰 `transform` 与 `opacity`，且能关
- [ ] 各平台宽度都过了一遍吗
- [ ] 冲突时按决策优先级排过吗
- [ ] 让位处写了理由吗
- [ ] 看过产物，而不是只看代码
