# 内容系统 · Voice & Tone

个人设计系统的文字层

管产物里说出口的每一句话，以及图上的字。视觉管看起来是什么样，这里管听起来是什么样。

只约束系统面：回执、卡片、帮助、报错、空态、推送。拟人化的人格另有调子，不在其内。

## 声音

三句话，任何场景都不变。

准确。说的是事实，有数字就给数字，没有就说没有，不猜、不夸大。写 `✅ 已提取 3 / 5 条`，不写 `✅ 提取完成，收获满满`。

克制。只说不说就会造成误解的话。不评价自己的输出，不替用户判断这很有用，不加语气词与感叹号。写 `⏳ 正在生成词云…`，不写 `⏳ 稍等片刻，马上就好啦！`。

直接。对「你」说话，先说结果，再说怎么办，出路给到能照做的粒度。写 `❌ 请引用一条包含图片或视频的消息后再发送`，不写 `❌ 未检测到媒体文件，建议您检查一下发送方式是否正确`。

## 语气

声音不变，语气随场景换。写新文案时先归到下表的某一类，再照着写。

| 场景 | 语气 | 句首符号 | 结构 |
| --- | --- | --- | --- |
| 成功 | 就事论事，不用形容词 | ✅ | 动作 + 结果（带数字） |
| 进行中 | 说清在等什么，不承诺时长 | ⏳ | 正在 + 做什么 |
| 失败 | 不道歉、不甩锅，说清卡在哪 | ❌ | 现象 + 出路 |
| 空态 | 平静，空不是错 | 📭 | 为什么空 + 怎么让它不空 |
| 引导 | 一个动作，一条能抄的命令 | 💡 | 做什么 + 怎么打 |
| 部分成功 | 说清哪部分成了、哪部分没成 | ⚠️ | 成了什么 + 没成什么 + 要不要重试 |

失败的出路按原因选一种，不三种混着写。用户输入问题就直接给正确写法（`❌ 请指定索引：智能体/索引`）。外部条件问题就说清是什么条件，让人能等或能改配置（`被上游限流了，过一会儿再试`）。自己的问题就如实说，并说明替代方案（`出图失败，先给你一份文字版`）。

## 写法

人称用「你」，不用「您」。「请」只用在必须强调这是一次请求的引导里，一条消息里至多一次。不用「吧」「哦」「啦」「呢」这类语气词，不用波浪线 `~`，不用感叹号 `！`。不评价自己的输出，「方便」「强大」「智能」「一键」这类词一个都不用。

一行以内的提示（状态、错误、空态、引导）句末不加标点（`❌ API 未配置`），句内正常用「，」。成段的文字标点正常用，末句加句号。省略号一律用「…」，不用 `...` 或 `。。。`。并列用「、」，不用「/」，除非在写两条可选命令（`on/off`）。

括号用全角「（）」，只有在写标识符、路径、命令时用半角 `()`。数字与单位之间不加空格（`3 条`、`2 秒`），数字与中文之间留一个空格（`共 24 条`、`3 个信源`）。冒号用全角「：」，后面不跟空格。

指令本体是唯一的例外，那里的数字紧贴中文（`近7天`、`裁剪 3x3`），因为用户要整条照打。写进正文引用时仍按上面的规则留空格。

一条消息至多三句。超过三句就是在写文档，搬进卡片或帮助页。先给结果，再给原因：写 `❌ 请指定索引：智能体/索引`，不写「索引参数没有提供，所以无法继续」。

数字写阿拉伯数字（`3`、`120`、`1.5 MB`），不写汉字数字，千分位只在四位以上用。时间用 24 小时制 `HH:MM`，日期用 `YYYY-MM-DD`，时长用「秒 / 分钟 / 小时」。

不写以机器为主语的句子：写 `❌ 图片下载失败`，不写 `❌ 系统检测到图片下载异常`。

指令一律叫「指令」，不叫「命令」「cmd」。写出来的指令要能整条抄走，带上当前前缀。参数占位必填用尖括号 `<名称>`，可选用方括号 `[路径]`，写进正文时用 `代码格式`。一条引导里只给一条指令，其余放到帮助页。

## 状态符号

一条消息开头至多一个符号，必须来自下表。这张表是符号的全集。

| 符号 | 角色 | 用在 |
| --- | --- | --- |
| ✅ | 成功 | 动作已完成并生效 |
| ⏳ | 进行中 | 等待、倒计时、正在处理 |
| 💡 | 引导 | 尚未开始、需要先做某事、可选提示 |
| ⚠️ | 有代价 | 成了一半，或成了但有折扣 |
| ❌ | 失败 | 没做成。输入不被接受，或外部条件不允许 |
| 📭 | 空 | 没有内容，但不是错误 |
| 📋 | 罗列 | 榜单、统计、清单、目录 |
| 🏆 | 高光 | 真正的胜利时刻，一次流程至多一次 |

一个符号只表示一种状态。拿不准时问一句：这条消息说的事成了没有。全成了用 ✅，成了一半或成了但有折扣用 ⚠️，没成用 ❌。

⚠️ 是全集里最少用到的符号。它变多，说明有人在拿它当「有情况」用。

| 常写成 | 为什么不对 | 改用 |
| --- | --- | --- |
| `⚠️ 未检测到媒体文件` | 什么都没做成，这是输入不被接受 | ❌ |
| `⚠️ 重启指令未开放` | 同上，指令被拒 | ❌ |
| `⚠️ 已清空 3 个对象的历史` | 全做成了，没有折扣可打 | ✅ |

图上不用符号。图有自己的视觉语言，符号会与它冲突。图要表达状态就画徽章。

不用表情符号代替标点，不用 🎉✨🔥 这类装饰性表情。

正文里另有一类行内记号，承担排版功能，不算状态符号：`▍` 标分区、`🔗` 标链接行、`📄` 标原文行。这一类只出现在纯文本的行首。状态符号出现在消息开头，两者不混用。

## 状态词

同一种状态在群里、在卡片上、在配置清单里得是同一个词。只有「格子里」允许用短写。

| 状态 | 用 | 不用 |
| --- | --- | --- |
| 开关（句子里） | 已启用 / 已停用 | 已开启、已关闭、已禁用、打开、关闭 |
| 开关（状态清单的一格） | 开 / 关 | 启用、停用（格子里太长） |
| 生命周期未跑完 | 待重启 | 待生效、需重启、待初始化 |
| 带条件的开关 | 已打开，后面括注是谁定的（`（本次设置）`／`（跟随全局）`） | 只写「跟随全局」（看不出当下开没开） |
| 可见性 | 公有 / 私有 | 公开 / 私人 |

同一个句子里不出现两组状态词。

## 空不是故障

这段时间没有数据和生成失败是两件事，不能用同一个符号。前者用 📭，后者用 ❌。写成 `❌ 生成失败：暂无数据` 有两个错：把空态说成了故障，又让用户去找一个并不存在的毛病。

实现上，底层把没数据与真失败分成两个返回值，上层分别渲染：

```text
📭 本群今日发言排行榜没有数据
换一个时间范围，或先让群里聊几句
```

推送侧的日志也分开。冷启动没数据是常态，用 `info!` 记一句就够。只在真失败时用 `warn!`。

## 通用术语

同一个概念，全项目只有一个说法。项目专有术语表在项目侧维护，同样只有一个说法。

| 用 | 不用 | 备注 |
| --- | --- | --- |
| 指令 | 命令、cmd | |
| 发送「x」 | 输入 x、使用 x、执行 x | 用户在输入框里做的事只有发送 |
| 引用 | 回复引用、quote | 引用某条消息后发送 |
| 配置键 | 字段、参数名、选项 | |
| 群 / 私聊 | 群聊、私信、频道 | 作通道名时统一这两个词 |
| 你 | 您、该用户 | 第二人称一律用你 |
| 重启 | 重载、重新启动 | |
| 出图 | 渲染、生成图片 | 指截图出卡时 |
| 额度 | 次数上限、配额 | 可用的次数 |
| 批量 | 清单、全部 | 枚举类指令名 |

未经确认的内部名（配置键、供应商名、模型名）照原样写，不改写、不翻译。那些是用户要去核对的东西。

## 卡片文案

一张卡片上的字分层，每层只放一类信息。

| 层 | 放什么 |
| --- | --- |
| 眉标 | 这张卡是什么。固定词，不随数据变 |
| 标题 | 本次的对象 |
| 副标题 | 范围与规模 |
| 小节 | 分区名 + 条数 |
| 条目 | 名称 + 键名 + 一句话说明 |
| 页脚 | 左：出处与口径。右：下一步动作 |

三条额外的要求。汇总出来的数字，卡片上要有一句话说明它怎么来的。推断出来的东西要说清是推断。每张卡的页脚给一条能立刻执行的指令。

## 检查清单

- [ ] 归到六类场景里的哪一类，语气对上了吗
- [ ] 一行以内的话句末有没有多余的句号，有没有语气词、波浪线、感叹号、自夸的词
- [ ] 失败与空态给了出路吗，出路是不是能照做的粒度
- [ ] 状态词是从状态词表里选的吗，句子里有没有混两组
- [ ] 符号是全集里的吗，只有开头一个吗，图上有没有混进符号
- [ ] 术语查过术语表吗，有没有把配置键翻译成中文
- [ ] 写出的指令能整条抄走吗，下一步明确给出来了吗
- [ ] 主语给的是事实吗

## 改规则的时候

改之前先看用户会不会因此对不上号。加状态词先看状态词表里有没有现成能用的。加符号只有当前全集表达不了才加，且要同时改这张表、改已有文案。改术语全项目一次改完，不能新旧并存。

改动落地时同步三处：这份文档、对应的组件文案（如果有）、实现里用到的文案本身。
