# 视觉系统 · Material 3 Expressive

我自己的设计系统 · 与[设计系统](design-system.md)、[交互系统](interaction.md)、[内容系统](content.md)三份配套。

本文管取值：色彩怎么推、对比度守到哪、字阶形状高度取几档、组件有哪些基元、什么情况下让位。视觉原则与令牌分工在[设计系统](design-system.md#令牌)。

本文的引号约定：「」引代码里真实出现的标识符与取值；“”提及行文中的某个说法或概念。

## 同源

同一套系统落在多个产物上时，用户看到的是前后脚出现的几张图、几个页面。这套系统管同源：色调节奏、圆角、字阶、阴影、组件形状来自同一份推导，各产物只留一支自己的色相。

产物之间形态不同不是问题，取值不同才是。**同源优先于令牌**：与外部实现并排出现的产物，逐项相同的数值比令牌统一重要，见[让位](#不适用范围与让位)。

## 令牌

色彩、字阶、形状、高度四类收成一个模块，只依赖标准库，输出 CSS 变量与常量，浏览器与 canvas 都能读。

模块可以按产物复制多份：产物各自发布时，多一个共享依赖就多一道发布顺序约束。代价是同步责任——改一处要几份一起改，改完要有办法校验。**要么单一来源，要么可校验的多份，不能既多份又不可校验。**

其余六类（Spacing、Size、Border、Opacity、Motion、State）的落点见[设计系统的令牌一节](design-system.md#令牌)。

## 色彩

一支色相推出六套色调板：

```text
palettesOf(hue, { chroma = 56, tertiaryShift = 60 })
  primary        (hue,                chroma)          → 56
  secondary      (hue,                chroma / 3.2)    → 17.5，下限 16
  tertiary       (hue + shift,        chroma / 1.8)    → 31.1，下限 28
  neutral        (hue,                4)
  neutralVariant (hue,                9)
  error          (36,                 68)              固定，不跟源色相
```

中性色取彩度 4 与 9，不取纯灰。成片的表面因此不带灰。错误色固定在色相 36，不跟源色相，在任何主题下都是红。

`lch(tone, chroma, hue)` 里的 tone 即 CIE L\*，0 黑 100 白。角色映射：

| 角色 | 明 | 暗 |
| --- | --- | --- |
| primary / secondary / tertiary / error | 板(40) | 板(80) |
| on* | 板(100) | 板(20) |
| *Container | 板(90) | 板(30) |
| on*Container | 板(30) | 板(90) |
| surface / background | neutral(98) | neutral(6) |
| onSurface | neutral(10) | neutral(90) |
| surfaceContainer 五档 | 100 / 96 / 94 / 92 / 90 | 4 / 10 / 12 / 17 / 22 |
| outline / outlineVariant | V(50) / V(80) | V(60) / V(30) |

`lch()` 给出的组合未必落在 sRGB 内。越界时二分降低彩度，色调与色相不变。整套系统的明度节奏由色调撑着，降彩度不改明度。彩度 0 的灰轴必在色域内，二分一定收敛。

### 与官方 M3 的偏差

官方 M3 用 HCT（基于 CAM16），本实现用 CIELCh，两者不等价。用 CIELab ΔE\*76 度量，中性色逐位吻合，彩色部分偏移，量级在 ΔE 2 到 5；色相与彩度取向更宽的第三色偏移更大。

偏差来自两处。HCT 与 CIELCh 的 tone 都是 L\*，中性色一致。彩色部分因为 CAM16 与 CIELab 对色相与彩度的定义不同而偏移。Expressive 本身的彩度取向更宽。

**本实现不复现官方色板的十六进制值。** 它保证同一支色相在任何产物里算出同一个值。

### 对比度

按 WCAG 相对亮度公式逐对测量，各值取最小：

| 配对 | 明色 | 暗色 | 等级 |
| --- | --- | --- | --- |
| `onSurface` / `surface` | 16.24 | 14.31 | AAA |
| `onSurfaceVariant` / `surface` | 8.84 | 10.82 | AAA |
| `on*Container` / `*Container` | 7.19 | 7.19 | AAA |
| `onPrimary` / `primary` | 6.41 | 7.66 | AA |
| `outline` / `surface` | 4.25 | 5.81 | 明色不到 AA |

最后一行是硬约束：

> **`outline` 是描边色，不用来写字。**

WCAG 对非文字的图形元素要求 3:1，`outline` 的 4.25 满足。正文要求 4.5:1，小字用 `outline` 会掉到线下。要降低存在感的文字用 `onSurfaceVariant`，层次交给字号与字重。

### 颜色不是唯一通道

只靠颜色传达的信息，都要有第二个通道。状态色块后跟文字说明，高对比度主题要能开，多档亲疏色每档都要有名字，排行榜的金银铜之外名次数字始终在场。

徽章里的数字不因为有了颜色就省掉。

### 系统外的颜色

头像主色、用户自选色这类系统外的颜色，过 `harmonize(hex, tone, chroma)`：只保留色相，色调与彩度换成系统取值。每个对象仍是自己的颜色，整张图的明度节奏是齐的。彩度低于 4 的灰色没有可用色相，退回一个回退色相。

## 每个项目一支色相

一套系统里的每个项目、每个子系统留一支自己的色相，彼此拉开距离。色相分配表在项目侧维护，本系统只规定三条：

- **暖色相的第三色偏移取 -60**，不取 +60。规范里的 +60° 是经验值，暖橙加 60° 会落到橄榄绿；改成 -60° 得到玫红或赤铜。
- **黄色系取较高的色调**。黄色在色调 40 上彩度被压缩，条形色一类需要辨识度的元素取色调 52 这一段。
- 与外部实现并排的产物取同一支色相，不与自己的色相冲突，见[让位](#不适用范围与让位)。

## 形状 · 字阶 · 高度

```text
圆角  none 0 · extraSmall 4 · small 8 · medium 12 · large 16 · largeIncreased 20
      extraLarge 28 · extraLargeIncreased 32 · extraExtraLarge 48 · full 9999
```

容器之间用圆角差分层，不加分隔线。列表首尾项的圆角放大到 `extraLarge`。

字阶是十五档标准 M3，`display`、`headline`、`title`、`body`、`label` 各三级。强调字重取 600：部分机器只装了 400 与 700 两档，写 500 会静默回落成常规字重，写 600 在这些字体集下匹配到 700。正文保持 400。比分、倒计时这类要对齐的数字走等宽栈，全局开 `font-variant-numeric: tabular-nums`。

高度是六档 `box-shadow`，卡片多数停在 level 1，层次主要交给容器色与圆角。

## 组件

统一 `m3-` 前缀。`baseline(scheme)` 出令牌与排版重置，`components()` 出组件样式。

| 类 | 用途 |
| --- | --- |
| `m3-card` / `--elevated` `--outlined` `--filled` | 卡片，四种形态 |
| `m3-chip` / `--primary` `--tertiary` `--error` `--outlined` | 药丸形 |
| `m3-list` / `m3-list-item` / `--accent` | 列表，用圆角与容器色分组 |
| `m3-badge` / `--gold` `--silver` `--bronze` | 序号徽章 |
| `m3-bar` / `__fill` `__track` | 进度与排行条 |
| `m3-header` / `__title` `__support` | 页眉 |
| `m3-footnote` | 页脚署名 |
| `m3-avatar` `m3-divider` `m3-surface` | |

前三名用金银铜，不用主题的主色、次色、第三色。名次的含义固定，跟着主题变色后不易辨认。三种金属色走 LCh，色调取 58、66、48。

进度条的填充与轨道是两个独立的全圆角色块，中间留 4px 空隙，长度用 flex 比例分配。

## 两端同色

部分图在页面里用 canvas 绘制，那里取不到令牌模块。把同一套 LCh 运算序列化进页面脚本，暴露 `M3.lch`、`M3.lchOf`、`M3.harmonize`。**两端算出的颜色必须一致**：改了色彩函数，页面脚本里的副本要同步改。

## 不适用范围与让位

复刻类画面不套这套系统，这是设计决定，不是遗漏：还原原作到逐像素的界面，套上设计系统后与原画面不符。作用于它的外壳，画面本身除外。文字规范不受此限，全部产物生效。

另有三类局部让位，也不是漏改：

| 让位的是 | 给谁 | 做法 |
| --- | --- | --- |
| 字阶与行高 | 用户自己的文档 | 用户发来的文档按文档的需要定字号，容器（圆角、边框、提示色）仍走令牌 |
| 少量颜色 | 外部素材本身 | 压在照片上的半透明遮罩、与外部取值绑定的白字，这两处写死，其余全套令牌 |
| 字号、等宽数字、角色色、形状、描边色 | 要与外部实现并排的产物 | 整套照搬外部实现的数值，改动时两边一起改 |

三条共一个原则：**不与内容争**。取值要么写死、要么让位，都在代码注释里写明理由。动这类代码之前先出一张图看一眼。
